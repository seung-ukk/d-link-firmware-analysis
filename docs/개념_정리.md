# 팀 실습 개념 정리

이 자료는 [README](../README.md)의 명령이 무엇을 증명하는지 설명한다. 각 개념은 실제 출력과 연결해 공부한다.

## 1. 펌웨어 포장과 신뢰 경계

배포 ZIP은 펌웨어 BIN과 릴리스 노트를 담는 배포 묶음이다. BIN의 `SHRS` 헤더는 암호화된 페이로드의 길이·IV·내부 검사값을 담는다. AES-CBC 복호화 후 `27051956` 매직의 uImage가 나온다. uImage에 담긴 커널 데이터는 LZMA로 압축돼 있다. 해제한 커널 안에는 별도로 압축된 initramfs가 있고, 이를 풀면 `070701` 매직의 newc CPIO 아카이브가 나온다. 이 CPIO에서 rootfs의 일반 파일과 디렉터리를 얻는다.

SHA-256은 **동일 파일 식별**에, ZIP CRC는 **압축 오류 확인**에 쓴다. SHRS 내부 SHA-512 일치는 복호화 결과와 이미지 내부 기록의 일치를 확인하지만 제조사 서명·배포 출처를 증명하지 않는다. 해시가 다르면 버전·파일·작업 단계를 먼저 확인한다.

## 2. MIPS ELF와 실행 환경

DIR-882의 `prog.cgi`, `lighttpd`, BusyBox는 MIPS Little Endian의 컴파일된 ELF 실행파일이다. `librcm.so`는 공유 라이브러리다. `file`은 형식을, `readelf -d`의 `NEEDED`는 동적 의존성을 보여준다. 심볼이 제거된 파일에서 `objdump`가 가까운 심볼명을 표시할 수 있으므로 함수명만으로 호출 위치를 단정하지 않는다. MIPS의 `a0`은 첫 번째 인자, `v0`는 반환값, `jalr`는 레지스터에 담긴 주소 호출, `bnez`는 값이 0이 아니면 분기하는 명령이다. 실제 주소와 GDB 관찰값을 함께 읽는다.

QEMU 사용자 모드는 MIPS 실행파일과 라이브러리를 호스트 안에서 실행한다. 완전한 공유기 부팅이나 커널·하드웨어 에뮬레이션이 아니다. Docker는 이 도구의 실행 공간을 분리한다. `--network none`, 읽기 전용 마운트, 권한 제거, 메모리·프로세스 제한은 실험 범위를 좁히기 위한 설정이다.

## 3. lighttpd, CGI, FastCGI, HNAP

`lighttpd`는 펌웨어의 웹 서버다. 설정의 `/HNAP1/` 경로는 FastCGI를 통해 `/bin/prog.cgi`로 연결된다. CGI는 웹 서버가 요청 정보를 프로그램에 전달하고 응답을 받는 방식이다. FastCGI는 요청별 환경 변수와 본문을 레코드로 전달하며 프로세스를 재사용할 수 있다. HNAP은 여기서 SOAP XML의 관리 기능 요청 형식이며 `SetPortForwardingSettings`가 포트포워딩 설정을 전달한다.

`fastcgi_probe.py`는 웹 서버 전체를 켜지 않고 **백엔드 방향의 FastCGI 클라이언트** 역할을 한다. 실제 MIPS `prog.cgi`에 요청을 보내고 QEMU·GDB 관찰을 JSON으로 저장한다. 그러므로 `prog.cgi`의 해당 입력 경로와 응답은 검증하지만 `lighttpd`의 HTTP 인증·라우팅을 검증하지는 않는다.

## 4. 입력 검증과 명령 주입

원본 실험에서 `LocalIPAddress`의 시험 문자열 `1$(>/tmp/d882)`은 `portforward_rule` 저장 호출 인자에 남았다. Hotfix 실험에서는 `tbsCheckIp`가 정상 IP에 `1`, 시험 문자열에 `0`을 반환했고, 시험 문자열은 저장 전에 거부됐다. `$(...)`는 셸의 명령 치환 문법이다. `>/tmp/d882`는 파일을 여는 리디렉션이라 셸이 해석하면 0바이트 마커를 남긴다. 마커의 생성은 방화벽 명령 성공과 다른 관찰값이다.

FastCGI 단계의 저장 호출과 Qiling 단계의 규칙 적용·셸 실행은 **서로 다른 실험**이다. Qiling에서는 앞에서 관찰한 규칙 문자열을 모의 NVRAM에 공급한다. 실제 MIPS `PORTFORWARD_run`·`twsystem` 코드와 펌웨어 BusyBox 셸을 실행하지만, NVRAM 조회·WAN 정보·최초 `fork` 자식 분기는 실험 코드가 대신한다. 정상 규칙에서 마커가 없고 시험 규칙에서만 생기는 대조가 명령 치환 효과를 뒷받침한다. 실제 공유기의 방화벽 적용이나 하나의 HTTP 요청에서의 연속 실행까지 증명하지는 않는다.

## 5. 증거를 읽는 순서

1. **입력 파일:** 공식 ZIP 이름, SHA-256, ZIP 내부 목록.
2. **변환 단계:** SHRS 검사, uImage 매직, LZMA 위치, CPIO 매직·항목 수.
3. **정적 경로:** `lighttpd.conf`, `file`, `readelf`, MIPS 역어셈블.
4. **요청 관찰:** 동일 FastCGI 도구로 원본·Hotfix 정상/시험 입력 네 경우의 SOAP·GDB 결과.
5. **후속 실험:** 원본 GDB에 남은 규칙을 모의 NVRAM으로 공급하고 정상/시험 규칙의 명령 인자·마커를 비교.
6. **한계:** 모의 지점, 오류 메시지, 미실행된 전체 서비스와 실물 장비를 별도로 명시.

팀원은 각 스크린샷에 **명령, 실제 출력, 그 출력으로 가능한 주장**을 한 문장씩 적어 서로 검토한다.
